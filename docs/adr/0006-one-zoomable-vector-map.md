# One continuously zoomable vector map, drawn with WebGL

The original draws the Campaign Level from a grid of bitmap tiles and the Full Map Level as a separate hi-res picture, and the port copies both into a 320 by 200 buffer that is scaled up. We want a remastered look in the manner of Tolkien's own maps: ink lines, forest edges, ridgelines and lettering, sharp at any size. We considered repainting the bitmaps at higher resolution, drawing vector art with Canvas 2D or SVG behind the two existing Levels, and one vector map drawn with WebGL.

We chose the last. The map is one body of vector geography (Terrain Regions, rivers and their crossings, roads, the map edge, Places), in the original map's pixel coordinates. Terrain Regions follow the tile grid exactly, since passability is per tile. The ground the map is drawn with (woods, mountains, coasts and rivers) is traced from the tiles' pixels, so it keeps the shapes the original's artist drew rather than the grid. A tool traces it from the extracted tiles, and hand corrections keyed to stable feature IDs are committed on top, since traced output, like all extracted data, stays gitignored. The map zooms continuously: the Full Map Level and the Campaign Level become its far and near zoom bands, deciding how Forces are drawn, by a level-of-detail policy (figure, compact, dot, then aggregated dots, with selected, watched and Ring-bearer Forces kept one tier more detailed), and which controls are offered. The Animation Level stays a separate view. The renderer is our own small WebGL2 code with no runtime dependency: polygons are triangulated by the tool, labels use a signed distance field font, and the original's pixel sprites are drawn crisp, between one and three times their original pixel size on screen, dropping a tier rather than shrinking further. Geography features carry a rank, so detail and labels are culled by zoom.

The source geography is GeoJSON in the original's pixel coordinates, with y pointing down, ignoring RFC 7946's geographic coordinate system. GeoJSON has no topology, so the build step snaps the borders that Terrain Regions share and rejects gaps and overlaps. Corrections are committed GeoJSON patches that replace, add or delete whole features by ID. The runtime loads a compiled binary bundle, never the GeoJSON. Elevation is for presentation only, since the original has none. Ridgelines and peaks are sparse vector features, inferred from mountain regions and then corrected. They drive the ink hill symbols and a faint wash, and never the sim.

The original bitmap renderer stays as the Classic mode, and the Map setting chooses between them (docs/spec/atlas-map.md). It is the visual reference for fidelity and the fallback where WebGL is unavailable.

This is staged against ADR-0002. At first the geography is presentation only, and the sim still reads the tile grid. Later the sim's terrain queries may be answered from the vector geography instead, but only once sampled answers agree with the tile grid away from region edges and every movement and reference-scenario test still passes. Any deliberate change to movement beyond that needs its own ADR, backed by Findings.

Its clause on drawing the original's pixel sprites on the Atlas map is superseded by ADR-0007.
